## 1. Bloquant — tout changement de réglage échoue sur macOS

**Symptôme.** Depuis le renderer, `window.nebulaHub.updateAppearance({ theme: 'light' })` est rejeté :

```
Error occurred in handler for 'settings:update-appearance':
TypeError: window2.setTitleBarOverlay is not a function
```

**Reproduction.**
1. Lancer `Nebula Hub.app` (build macOS).
2. Réglages → changer le thème (ou n'importe quel réglage d'apparence).
3. L'appel IPC est rejeté avec l'erreur ci-dessus.

Reproduit par script (Chrome DevTools Protocol, `--remote-debugging-port`) :
`window.nebulaHub.updateAppearance({theme:'light'})` → `ERR Error invoking remote method 'settings:update-appearance': TypeError: window2.setTitleBarOverlay is not a function`.

**Cause.** `BrowserWindow.setTitleBarOverlay()` n'existe que sous Windows et Linux ; sur macOS la méthode est `undefined`.
- `src/electron/window.ts:55` — `applyWindowTheme()` l'appelle sans test de plateforme.
- `src/electron/main.ts:296` — `broadcastSettings()` appelle `applyWindowTheme()` ; il est utilisé par **tous** les handlers de réglages (`main.ts:324`, `341`, `480`, `539`).

Conséquence : le réglage est écrit dans `settings.json` (l'écriture a lieu avant), mais `broadcastSettings` s'interrompt avant `updateTray()`, et le renderer reçoit une erreur. Le broadcast Nebula Link (`link.broadcastAppearance`) a lieu avant l'erreur, le renvoi `settings:changed` aussi.

**Correctif proposé (sans effet sur Windows).** Même garde que Nebula Clock (`apps/desktop/src/windows.ts:36`) :

```ts
if (process.platform !== 'darwin') window.setTitleBarOverlay(titleBarOverlay(settings));
```

## 2. Élevée — exception non gérée au changement de thème du système

**Cause.** `src/electron/main.ts:172` :

```ts
nativeTheme.on('updated', () => applyWindowTheme(settingsStore.get()));
```

Sur macOS, `nativeTheme` émet `updated` quand le système passe en clair/sombre (manuellement ou en mode « Automatique » au coucher du soleil). `applyWindowTheme` lève alors la même `TypeError` que le bug 1, cette fois **hors de tout handler IPC** : exception non gérée dans le processus principal (Electron peut afficher la boîte « A JavaScript error occurred in the main process »).

Déduit du code et du bug 1 (même ligne fautive). Pas déclenché pendant le test pour ne pas modifier le thème système de la machine. Corrigé par le même garde que le bug 1.

## 3. Moyenne — chemins de sauvegarde avec `\` en dur (3 tests en échec hors Windows)

`npm test` : **3 échecs / 965** (38 suites sur 39 OK), tous dans `tests/electron/install-manager.test.ts`, bloc « backup choices, copy and export (ADR-026) » :

- `keeps the backup in Documents and copies it to the chosen folder`
  ```
  Expected: "<tmp>/Copies/Nebula Finterest/Documents\Nebula Finterest\finterest-store-backup-….json"
  Received: "<tmp>/Copies\Nebula Finterest\finterest-store-backup-….json"
  ```
- `reports a failed copy without blocking the operation` : `copyState` attendu `failed`, reçu `ok`.
- `exports the data on demand, checked and copied, and refuses what it cannot do` : `result.path.startsWith(path.join(root, 'Documents', 'Nebula Finterest'))` → `false`.

**Cause.** `src/shared/backup.ts:29` et `:39` assemblent les chemins avec `\\` en dur, alors que les tests utilisent `path.join` (séparateur `/` sur macOS/Linux). Sur macOS le résultat est un nom de fichier unique contenant des `\` dans le dossier parent. Les tests passent sous Windows, d'où l'absence de signal en CI.

**Correctif proposé.** Choisir le séparateur selon la plateforme (`process.platform === 'win32' ? '\\' : '/'`) ou `path.join` côté main. Sans effet sur Windows.

## 4. Info / conception — fonctions Windows uniquement

Ce n'est pas un bug au sens strict (le CLAUDE.md décrit le Hub comme une app Windows), mais sur macOS, sans plantage visible :

- **Détection des apps installées** : `reg.exe export` et `tasklist.exe` (`src/electron/apps/system-probe.ts:44`, `:56`) → aucune app n'est jamais vue comme installée.
- **Installation / mise à jour** : le catalogue ne référence que des `.exe` NSIS et `latest.yml` (`catalog/nebula-catalog.json`, `exeName: "*.exe"`) ; pas de `latest-mac.yml` ni de `.dmg/.zip`.
- **Nebula Link** : le canal est un named pipe `\\.\pipe\nebula-link-<hash du SID>` obtenu via `whoami.exe` (`src/electron/link/session.ts:27`, `:34`). Sur macOS, `net.listen()` sur ce chemin crée une socket Unix avec un nom littéral contenant des `\`, relatif au dossier courant ; en lançant depuis le Finder (dossier courant `/`) l'écoute risque d'échouer. L'UI affiche quand même « À l'écoute ».
- **Mise à jour du Hub** (`install/hub-updater.ts`) : lance un installeur NSIS.

Pistes macOS si un portage est voulu : `mdfind`/`/Applications/*.app` + `Info.plist` pour la détection, `ps -axo comm` pour les processus, `open -a` pour lancer, socket Unix dans `app.getPath('userData')` pour Link, artefacts `dmg/zip` + `latest-mac.yml` dans le catalogue.
