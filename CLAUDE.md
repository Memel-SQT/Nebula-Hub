# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Nebula Hub** (the brief calls it "Nebula Store"; renamed by ADR-013) is a Windows desktop app that is to the Nebula app family what the Microsoft 365 portal is to Office: a launcher, a store (catalog, install, update, repair, uninstall with integrity checks), and the hub of **Nebula Link**, the local IPC layer through which the apps share appearance, deep links, widgets and notifications under explicit user consent. Single user, local, no account, no telemetry; the network is only used to read the signed catalog and download installers. Every Nebula app keeps working **standalone**, with or without the Hub.

The project is built milestone by milestone (M0 → M9) from a French brief; each milestone ends with a stop and a French report. Decisions live in `docs/DECISIONS.md` (ADRs, never rewritten, only amended by a new ADR); the discovery of the sibling repos is in `docs/DISCOVERY.md`.

## Commands

```bash
npm install                 # Node >= 22.12 (Electron 44). npm >= 11 gates install scripts:
                            # electron/esbuild are approved in package.json "allowScripts"; after
                            # bumping them run `npm approve-scripts electron esbuild`
npm run dev                 # Vite (127.0.0.1:5173) + tsup --watch + Electron
npm run build               # renderer (vite) then main + preload (tsup)
npm run typecheck           # tsc --noEmit
npm run lint                # eslint (typescript-eslint + react-hooks), src, tests, packages
npm test                    # jest (ts-jest; jsdom by default, `@jest-environment node` for main tests)
npx jest tests/renderer/screens.test.tsx   # a single test file
npm run dist:win            # NSIS installer -> install/windows/Nebula-Hub-Setup-<v>.exe
npm run catalog:sign        # validate + sign catalog/nebula-catalog.json (NEBULA_CATALOG_KEY = private key path, outside the repo)
npm run link:demo           # Nebula Link test bench, narrated (test-mode Hub + two fake apps over real pipes)
npm run link:pack           # build @nebula/link (CJS + ESM + types) -> install/link/nebula-link-<v>.tgz
```

Run the built renderer without packaging: `NEBULA_HUB_USE_BUILD=1 electron .`. Point any manual run at a throwaway data folder with `NEBULA_HUB_USER_DATA_DIR=<dir>` (never set in a packaged install). Logos and app icons are regenerated by `scripts/render-logos.ts` (see its header: resvg + png-to-ico installed outside the project).

Real installs are only tested in Windows Sandbox (`scripts/sandbox.ps1 [-Recipe m4|m5]`, automated recipes in `scripts/sandbox/`, results in the git-ignored `.sandbox/results`, plan in `docs/TEST_PLAN_WINDOWS.md`), never on the development machine's own Nebula apps: in any live check there, open confirmation dialogs only to cancel them.

All four of `typecheck`, `lint`, `test` and `build` must pass before any milestone report.

## Architecture

npm workspaces. TS path aliases (`@shared`, `@renderer`, `@nebula/design`, `@nebula/design/react`) are mirrored in `tsconfig.json`, `vite.config.ts` and `jest.config.ts`.

- **`src/electron/`** — main process. `main.ts` pins `userData` to `%APPDATA%\Nebula Hub` (ADR-007/013), takes the single-instance lock, registers IPC; `window.ts` creates the one hardened window (frameless, themed `titleBarOverlay`, close-to-tray, visibility events); `security.ts` applies process-wide hardening (sandbox everywhere, no permission granted, no webview/navigation/new window, no app menu, `isTrustedSender` on every IPC); `settings-store.ts` owns `settings.json` (atomic writes via `fsutil.ts`, serialized chain); `tray.ts` is the tray; `db.ts` is `store.sqlite` (sql.js, explicit transactions, atomic writes, additive migrations only); `net/http.ts` is the only network client (allowlist checked on every redirect hop); `catalog/catalog-service.ts` fetches, verifies (Ed25519 + schema) and caches the catalog and each app's release and `latest.yml` (docs/CATALOG.md, ADR-019); `apps/installed-apps.ts` detects installed family apps (registry, running processes) and launches them, with every Windows call behind `apps/system-probe.ts` so it is tested without Windows (ADR-020). Launch paths are rebuilt in main from the detected location and the catalog's `exeName`; the renderer only sends an app id and never sees uninstall commands. `net/download.ts` streams installers to `.part` files (allowlist on every hop, size cap, HTTP Range resume) and `verifyFile` checks size + SHA-512; `install/install-manager.ts` runs one operation at a time through the state machine of `shared/install-state.ts` (download → verify → wait for the user to close the app → silent install with `shared/installer-args.ts` → detection decides), with `install/history.ts` (`install_history`) and `install/installer-runner.ts` (spawn, no shell, never kills on timeout) (ADR-021). M5 (ADR-022) adds update/repair (`--updated /S`), uninstall (registry command validated by `shared/uninstall-command.ts`, then wait for the key to disappear), the app's own backup before any of them (`shared/backup.ts`, file shape checked, `backup-failed` waits for a second confirmation), `plan()` for the confirmation screen, polite close on user request only, and opt-in automatic updates. The main process refuses unconfirmed repairs, uninstalls and updates of apps that back up their data. `link/` is Nebula Link (docs/NEBULA_LINK.md, ADR-023/024): `link-server.ts` (named pipe, mutual HMAC handshake, routing of query/event/intent/notify with consent checks, limits), `link-store.ts` (consents, journal without content, notifications), `session.ts` (per-user pipe from the SID, session file, installed manifest reader), `link-hub.ts` (wiring, the Integrations view, the activity center), `widgets.ts` (M7, ADR-025: the Home widgets read as `nebula.hub`, values in memory only, paused and private values dropped while the window is hidden). `dock.ts` (ADR-027) is the Hub mode: an app keeps its own process and window, and the Hub sends it alone (`nebula.hub.dock`, DockV1) the screen bounds of the `docked` screen to lay its frameless window over, one docked app visible at a time, all released when the Hub quits. `notifier.ts` relays the activity center to Windows when the Hub is not focused (private notifications never show their text there).
- **`src/electron/preload.ts`** — the single bridge `window.nebulaHub` (typed by `NebulaHubBridge` in `src/shared/bridge.ts`): one method per action, never a generic `invoke(channel)`. It reads the initial state synchronously (theme/language right on first paint).
- **`src/shared/`** — pure, tested modules used by both sides: settings parsing/merging (field by field: a bad value never breaks the others), the IPC contract, URL validation (R12), main-process strings. Everything decidable without I/O goes here.
- **`src/renderer/`** — React 18 UI, no router: navigation is typed state (`navigation.ts`). `screens/` (one per section, each handling loading / empty / offline / error / ready through `components/ScreenState.tsx`), `components/` (Finterest dashboard grammar: `SummaryCard`, `Panel`, `AppTile`…), `brand/` (the three logo proposals as pure data, `HubMark`), `i18n/` (fr/en per domain, same API as Finterest), `catalog.ts` (helpers over the `CatalogView` pushed by the main process), `components/Markdown.tsx` (release notes from marked tokens, never HTML).
- **`packages/nebula-design`** (`@nebula/design`) — the shared Nebula look, ported from Nebula Finterest v0.1.36 (ADR-009, ADR-014): tokens and the four themes (CSS), `appearance.ts` (accent presets, `accentVariables`, field-by-field parsers, `NebulaAppearance` = the I1 broadcast object), `sound.ts`, `effects.ts`, `BackgroundFx`, `Icon`, `Splash`. Framework-free entry (`index.ts`, safe in a main process) vs React entry (`react.ts`). It has no dependency on the Hub: Finterest, Clock and News adopt it in M8.
- **`packages/nebula-link`** (`@nebula/link`) — the Link protocol and the client SDK the apps install (zero dependency; framing, proofs, manifests, schemas, deep links, `NebulaLink` client). The Hub's server imports the same sources, so both sides validate identically. `tests/link-harness/` is the test bench (fake apps Alpha/Beta, raw client, test-mode Hub).

### Data flow

Renderer → `window.nebulaHub.<method>()` → `ipcMain` handler (trusted sender only) → store/service → fresh state returned and re-synced by the renderer (same principle as Finterest). Appearance changes apply optimistically, are persisted in `settings.json`, broadcast back (`settings:changed`), and re-theme the native window controls.

## Invariants [CRITIQUE] — never break these

- **R02** No installer runs before its size and SHA-512 match the release `latest.yml` from an allowed source. **R03** The catalog is Ed25519-signed; an invalid signature is rejected and the last valid cached catalog is used. **R05** HTTPS allowlist only (`api.github.com`, `github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com`, `raw.githubusercontent.com`, `git.rodriguesnoa.fr`), redirects to other hosts refused; the renderer has no network (`connect-src 'none'`).
- **R04 / brief 7.6** No uninstall, repair or Finterest update without explicit confirmation stating what happens to the data. Before any update/repair/uninstall of Finterest: run `"<InstallLocation>\Nebula Finterest.exe" --backup-before-uninstall=<Documents>\Nebula Finterest\finterest-store-backup-<timestamp>.json`, then **validate the file content** (Finterest always exits 0); block on failure unless the user confirms twice. The confirmation's "back up first" box is ticked by default; unticking it (ADR-026) is the only other way to skip the backup, never for automatic updates. Backups stay in `Documents\<app>` (the root the app reads first); the optional copy folder only gets a duplicate.
- **ADR-004** Installer arguments: fresh install `/S` (+ `/D=<dir>` last, unquoted); update and repair `--updated /S`; **never** `--delete-app-data`, never `/D` on update/repair. A silent NSIS installer kills the running app: close it with the user's consent first (R08). Re-read the installed version after closing the app and after any failure (the app's own `autoInstallOnAppQuit` may have run). An NSIS uninstaller returns immediately: wait for the registry key to disappear.
- **R07** The Hub never reads another app's data; data only arrives through Nebula Link, declared by the app and authorized by the user. Backups are produced by each app (ADR-016).
- **R10** `contextIsolation`, `sandbox`, no `nodeIntegration`, build-time CSP (`vite.config.ts`), single preload bridge, `webSecurity`, navigation/`window.open` blocked, single-instance lock. **R11** No shell: `execFile`/`spawn` with argument arrays (ESLint forbids `exec`/`execSync`); no path built from remote data without validation. **R12** Remote markdown is rendered from `marked` tokens to React (ADR-005), no raw HTML; links go through `openExternal` after `isSafeExternalUrl`.
- **Nebula Link**: nothing but `link.hello`/`link.auth` is answered before the mutual handshake, and the token never travels; an app is admitted only if installed and its installed manifest hash matches; only declared capabilities are served, every result/payload is schema-checked; private capabilities need the user's yes per pair; the journal never holds contents; widget values are never written to disk. Link must stay optional for the apps (R09): the SDK never throws or blocks when the Hub is absent.
- Registry: read with `reg.exe export` (UTF-16), not `reg query` (ADR-003). `InstallLocation` lives in `Software\<GUID>`, not in the Uninstall key.

## Conventions

- Code, comments, commits and this file in English; `README.md`, `docs/` and milestone reports in French.
- No hard-coded user-facing string (i18n, fr and en together — `i18n.test.ts` checks parity); no color outside a token block; only `opacity`/`transform` animated, one infinite animation on screen (the background), every effect honours `data-motion` and `prefers-reduced-motion`; icons from `Icon` (no Unicode glyphs).
- Any module ported from a sibling repo says so in its header. Sibling repos (Nebula-Finterest, nebula-clock, Nebula-News) are read-only until M8; then one repo at a time on `feat/nebula-link`, following that repo's own `CLAUDE.md`.
- `DEV_CHANGES.md`: a new dated section on top for each session. Release notes only in the GitHub release body. The family repos are public: no personal path or user data in docs or logs.
- Never push to a remote without the user's explicit consent.
